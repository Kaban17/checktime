# CheckTime — дизайн приложения

Дата: 2026-09-15. Статус: согласован.

## 1. Цель

Android-приложение для учёта времени. Каждые N минут поверх других приложений
появляется экран, на котором пользователь распределяет прошедшее время между
категориями. Учёт непрерывный: все 24 часа в сутки должны быть расписаны, дыры
невозможны. Распределение можно отложить; нерасписанное время накапливается в
один хвост и распределяется целиком при следующем показе.

## 2. Модель данных

### 2.1 Сущности (Room)

| Сущность   | Поля                                                   |
|------------|--------------------------------------------------------|
| `Group`    | `id, name, color, sortOrder`                           |
| `Category` | `id, groupId, name, color, sortOrder, archived`        |
| `Segment`  | `id, startAt, endAt, categoryId` — unix-мс, UTC        |

- Два уровня иерархии: группа («Личное», «Работа») → категория («Сон», «Спорт»).
- Время назначается только на категорию, никогда на группу.
- Архивная категория не показывается на экране распределения; её сегменты
  остаются и учитываются в статистике.
- Категорию с сегментами можно только архивировать; удалить — только пустую.
  Группу удалить можно только пустую.
- Инвариант таймлайна: сегменты не пересекаются и покрывают
  `[trackingStart, accountedUntil)` без дыр.

### 2.2 Состояние

Состояние учёта хранится в Room, в таблице `tracking_state` с единственной
строкой — так `allocate` может проверить и сдвинуть `accountedUntil` в одной
транзакции с записью сегментов:

| Поле              | Смысл                                                        |
|-------------------|--------------------------------------------------------------|
| `trackingStart`   | Момент начала учёта (кнопка «Начать учёт»). До него попапов нет. |
| `accountedUntil`  | Граница «до сюда всё расписано». Хвост = `[accountedUntil, now)`. |

Настройки — в DataStore Preferences:

| Ключ              | Смысл                                                        |
|-------------------|--------------------------------------------------------------|
| `intervalMinutes` | N — период показа попапа.                                    |
| `snoozeMinutes`   | На сколько откладывать.                                      |
| `stepMinutes`     | Шаг степпера на экране распределения (по умолчанию 5).       |

### 2.3 Семантика распределения

- При открытии экрана фиксируется `end = now`, `total = floor((end − accountedUntil) / 60 с)`.
  Работа идёт целыми минутами.
- Пользователь раздаёт `total` минут по категориям. Сегменты пишутся подряд в
  порядке списка категорий — упорядоченность нужна для будущего
  последовательного режима ввода («первые X минут → категория»).
- После сохранения `accountedUntil += total · 60 с`. Остаток меньше минуты
  уезжает в следующий хвост.
- Хвост короче одной минуты — попап не показывается.
- Сохранение — одна транзакция Room, внутри которой проверяется, что
  `accountedUntil` не изменился с момента открытия экрана; иначе сохранение
  отклоняется и экран перезагружает хвост.

### 2.4 Правка прошлого

Операции `TimelineRepository`, каждая — транзакция, после каждой инвариант
сохраняется:

- `changeCategory(segment, category)`;
- `moveBoundary(left, right, newTime)` — двигается граница между соседями,
  а не сегмент, поэтому дыры не возникают;
- `split(segment, time)` — разбить на два (категория наследуется);
- `merge(left, right)` — слить соседние с одной категорией.

## 3. Планировщик и попап

### 3.1 Будильник

- Один точный будильник (`AlarmManager.setExactAndAllowWhileIdle`), всегда
  переставляется, очереди нет.
- После сохранения: `accountedUntil + N мин`. После откладывания:
  `now + snoozeMinutes`.
- Разрешения: `USE_EXACT_ALARM` (13+, выдаётся автоматически) и
  `SCHEDULE_EXACT_ALARM` для Android 12.
- `BootReceiver` (`BOOT_COMPLETED`) и `MY_PACKAGE_REPLACED` переставляют
  будильник; если он уже просрочен — срабатывает сразу.

### 3.2 `AlarmReceiver` и `UnlockWatcherService`

Попап **никогда** не показывается сам по будильнику и не включает экран.
Он появляется только в момент разблокировки телефона (если распределение
«назрело») и по явному действию пользователя (3.5).

`AlarmReceiver` (по будильнику, после загрузки и после обновления приложения):

1. Если учёт не начат или хвост < 1 мин — снимает уведомление, ставит
   будильник на `accountedUntil + N`.
2. Иначе — постит ongoing-уведомление «Не расписано: X мин» (канал высокого
   приоритета, `setOnlyAlertOnce`: heads-up один раз, дальше обновляется молча;
   `contentIntent` на `AllocationActivity`), ставит следующий будильник на
   `now + N` и запускает `UnlockWatcherService`.

`UnlockWatcherService` — foreground-сервис (тип `specialUse`), чьё
foreground-уведомление — то же самое уведомление «Не расписано» (id 1), так что
в шторке ничего лишнего не появляется. Его существование и означает «попап
назрел». Он слушает `ACTION_USER_PRESENT`; при разблокировке, если хвост ≥ 1 мин
и выдано `SYSTEM_ALERT_WINDOW`, запускает `AllocationActivity` и останавливается.
Если телефон в момент будильника уже разблокирован и используется — попапа нет
до следующей разблокировки. «Готово» и «Отложить» останавливают сервис;
после «Отложить» он снова запустится только по snooze-будильнику.

Запуск активности из сервиса разрешён благодаря `SYSTEM_ALERT_WINDOW`
(исключение из запрета фоновых запусков); запуск foreground-сервиса из
`AlarmReceiver` разрешён благодаря точному будильнику. Уведомление висит, пока
хвост непуст (обновляется по будильнику и при заходе в приложение), снимается
при сохранении.

### 3.3 `AllocationActivity`

- `launchMode=singleTask`, `taskAffinity=""`, `excludeFromRecents`. Не входит в
  навигацию главного экрана. Над экраном блокировки не показывается — в этом
  нет нужды, попап приходит после разблокировки.
- Шапка: `14:00 – 14:47 · 47 мин`, счётчик `осталось: 12 мин` (красный, пока ≠ 0).
- Список категорий, сгруппированный по группам. Строка:
  `[название] [−] 25 [+]`. Тап по названию — отдать весь остаток. Шаг из
  настроек; долгое нажатие — автоповтор.
- Кнопки: **Отложить** (на `snoozeMinutes`) и **Готово** (активна только при
  остатке 0). Жест «назад» = Отложить.
- Повторное срабатывание будильника при открытом экране ничего не меняет
  (`singleTask`); двойная запись исключена проверкой в транзакции (2.3).

### 3.4 Разрешения и онбординг

Чеклист на главном экране с кнопками перехода в системные настройки:

- «Поверх других приложений» — обязательно; «Начать учёт» заблокирована без него.
- «Уведомления» (Android 13+).
- «Точные будильники» — только если система не выдала автоматически.
- Подсказка отключить оптимизацию батареи.

Без overlay приложение работает, но попапов нет — только уведомление; пункт
чеклиста подсвечен красным.

### 3.5 Ручной вызов

Кнопка «Распределить сейчас» на главном экране и тап по уведомлению открывают
ту же `AllocationActivity`.

## 4. Структура приложения

Один Gradle-модуль `app`, пакет `dev.boar.checktime`. DI — ручной
`AppContainer` в `Application`, без Hilt.

```
data/        Room: entities, DAO, AppDatabase; SettingsRepository (DataStore)
domain/      TimelineRepository — единственное место записи сегментов и
             сдвига accountedUntil; чистые функции статистики и нарезки по дням
scheduler/   AlarmScheduler, AlarmReceiver, BootReceiver, PendingNotification
ui/          Compose-экраны + ViewModel'и, Compose Navigation
```

### 4.1 Экраны

Нижняя навигация: **День · Статистика · Настройки**.

- **День** — дата с перелистыванием; итоги по категориям за день; список
  сегментов `14:00–14:25 Работа / Код`. Сверху плашка «Не расписано: X мин →
  Распределить», если хвост непуст. Тап по сегменту — шторка: сменить
  категорию, разбить в точке, слить с соседом, сдвинуть границу с соседним.
- **Статистика** — период (сегодня / неделя / месяц / произвольный); таблица
  «группа → категории: часы, %», раскрываемая по группам; горизонтальная столбчатая
  диаграмма по категориям на Canvas без внешних библиотек.
- **Настройки** — интервал N, время откладывания, шаг степпера; чеклист
  разрешений; «Начать учёт» / «Распределить сейчас»; раздел **Категории**:
  список групп с категориями — добавить, переименовать, цвет, порядок
  кнопками ▲/▼ (перетаскивание — возможное улучшение позже), архивировать.

### 4.2 Первый запуск

Создаётся стартовый набор: Личное (Сон, Еда, Спорт, Отдых), Работа (Работа).
Всё редактируется.

## 5. Технологии

- Kotlin 2.2, AGP 9.x, Gradle 9.6, Compose BOM 2026.09, Material 3, Room 2.8
  (KSP), DataStore Preferences, Compose Navigation.
- `minSdk 26`, `targetSdk 36`. Сборка под JDK 21.
- Язык интерфейса — русский, строки в `strings.xml`.

## 6. Граничные случаи

- **Часовой пояс / перевод часов**: сегменты в UTC, отображение по локальной
  зоне; день считается от локальной полуночи; сегмент через полночь в дневных
  итогах режется по границе.
- **Время откатили назад** (`now < accountedUntil`): хвост пустой, попап не
  показывается, на экране «День» — предупреждение. Вперёд — просто длинный хвост.
- **Процесс убит / приложение смахнули из недавних**: состояние в
  DataStore/Room, будильник переживает смерть процесса — ничего не теряется.
- **Отказ в overlay**: см. 3.4.

## 7. Тестирование

- **Unit (JVM, Robolectric + in-memory Room)**: `TimelineRepository` —
  `allocate`, `split`, `merge`, `moveBoundary`, `changeCategory`; после каждой
  операции проверяется инвариант «нет дыр и пересечений»; отклонение
  сохранения при изменившемся `accountedUntil`. Чистые функции: статистика по
  периоду, нарезка по дням, расчёт следующего будильника.
- **Планировщик (Robolectric)**: `AlarmReceiver.handle` показывает уведомление,
  ставит следующий будильник и запускает `UnlockWatcherService`, но не
  активность; `UnlockWatcherService` по `ACTION_USER_PRESENT` запускает
  `AllocationActivity` при выданном overlay и хвосте ≥ 1 мин, иначе только
  останавливается.
- **Телефон (Android 16)**: ручной чеклист — уведомление по будильнику без
  попапа, попап при разблокировке, откладывание, сохранение, перезагрузка.

## 8. Этапы реализации

1. **Ядро**: группы/категории, настройки, планировщик, `AllocationActivity`,
   откладывание, уведомление о хвосте, экран «День» (только просмотр).
2. **Прошлое**: правка сегментов (2.4) и шторка на экране «День».
3. **Статистика**: экран с периодом, таблицей и диаграммой.

Каждый этап — работающее приложение.

## 9. Вне рамок

Экспорт CSV, последовательный режим ввода, тренды и тепловая карта по часам,
вложенность глубже двух уровней, виджеты, бэкап.
